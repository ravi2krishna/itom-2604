    -> In Terms Of Business / In Company 

        -> A Workflow is the path a task follows from 

            Request -> Approval -> Action -> Completion 

        
        -> IT Support Workflow 

            One Of The Employees Says: My Laptop Is Not Working 

            Step - 1 

                -> Employee Raises A Ticket 

                    My Laptop is not starting - submitted via IT Portal/Help desk tool

                    Ticket Created In System (*)

            Step - 2
                
                -> Manager Approval

                    Manager Reviews Request and Approves 

                    Auto / Mandatory / Optional (*)
            
            Step - 3

                -> IT Team Receives Request  

                    Ticket is assigned to IT Help desk Queue 

                    SLA Timer Starts (*)

            Step - 4

                -> Technician Checks Issue 

                    Technician Visits Employee or Connects Remotely (Hardware / Software)

                    Technician Assigned (*)

            Step - 5
                
                -> Laptop Needs Repair / Replacement 

                    Issue Fixed On Spot / A Replacement Device is Provided from IT Inventory 

                    Resolution Captured (*)

            Step - 6

                -> Ticket Closed 

                Employee Confirms Issue is resolved, ticket is closed 

                Workflow Completed (*)

Class - 4
===========

    -> Modules / Key Concepts Of ITOM 

        -> CMDB (Configuration Management Database)

            -> The Backbone Of ITOM 

            -> All Discoverd Assets and Their Attributes(Properties)
            are Stored in CMDB As Configuration Items (CI's)

        
        -> Configuration Items (CI's) 

            -> Any Component That Needs To Be Managed 

                -> Server, Router, Database, Application etc 

            -> All the CI's are Stored / Updated in CMDB

        
        -> Service Discovery

            -> The Automated Process Of Identifying and Populating CI's 
            into CMDB, Using MID Server. 

        
        -> MID Server 

            -> M - Management

            -> I - Instrumentation

            -> D - Discovery 

            -> A Mid Server is an Java Based Application(Agent) Which is Installed 
            Within Your Customer Network Machine (Cloud / On-Premise)

            -> Mid Server Acts As A bridge between 
            ServiceNow Instance (PDI) and Target Customer Infrastructure.


        -> Service Mapping 

            -> Service Mapping Creates A Map Linking Your Business Service(Ecommerce) 
            To All The Dependent Infrastructure Components.

    

    -> CMDB (Configuration Management Database)

        -> The ServiceNow Configuration Management Database (CMDB) is a 
        centralized data repository that stores a logical model of an 
        organization's IT infrastructure, applications, and services.

        -> CMDB Is Master Inventory Of ServiceNow Operational Implementations. 

        -> Every Server, Every Application, Every Printer, Every Storage Device etc
        all of these lives as Records In CMDB         

    
    -> Customer Email Service Down Scenario 

        -> Email Software - CI 

        -> Email Software Requires Tomcat Server - CI 

        -> Tomcat Server Requires Java Environment - CI 

        -> Java Environment Needs Operating System Linux - CI 

        -> Linux Operating System Needs To Run On Hardware - CI 


    -> NOTE: So CMDB Answers Important Things 

        -> What Do We Have ? 

        -> Where Is It ?

        -> How Everything Is Connects ?

Class - 5
===========

    -> Configuration Items (CI's)

        -> A Configuration Item (CI) in servicenow is a digital Record 
        within the CMDB, representing "Any Manageable IT Component"
        such as Servers, Applications, Network Devices etc 

        -> CI's Track Infrastructure Details (Manufacturer, Vendor, Locations)
        to Support ITIL Process 

        -> Any Configuration Item Has Three Things 

            -> Class (What Type Of Asset Is It)

                -> Windows Computer 

                -> Linux Server 

                -> Application 

                -> etc 

            
            -> Attributes (Properties Of Asset)

                -> Manufacturer 

                -> Operating System 

                -> CPU Type 

                -> Disk 

                -> RAM 

                -> etc 


            -> Relationships (Connection With Other Assets)

                -> A Relationship In ServiceNow is a Connection 
                between Multiple Configuration Items, which defines 

                    -> How They Interact With Others 

                    -> How They Depend On Others 

                    -> Few Examples Include 

                        -> Runs On (An Application Runs On Server)

                        -> Used By (Configuration File Is Used By Application)

                        -> Depends On (Business Service Depends On An Application)

                        -> Connected By (A Server Is Connected By Switch)

                
                -> NOTE: The Relationships are automatically Discoverd During 
                Service Discovery, and all the Discoverd Relationships are updated in CMDB
